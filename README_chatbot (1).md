# RAG Chatbot for Documents (PDF / TXT / CSV)

Chat with your own PDFs, text files, and CSVs. Every answer cites exactly which chunk of which
file it came from. Backend: **FastAPI**. Model + embeddings: **Google Gemini**. Vector store: **Chroma**.

## What it does
- Upload PDF, TXT, and CSV files
- Loads → chunks → embeds → indexes in a local vector store
- Answers are generated **only** from retrieved content, with inline `[source#chunk_id]` citations (click one to read the chunk)
- If nothing relevant is retrieved, it says so instead of guessing

## How it works
```
upload → load → chunk → embed + index → retrieve + answer
```
1. **Chunking is type-aware.** Prose is split by *token* count with overlap (`src/chunking.py`, tiktoken); CSV rows stay one chunk each.
2. **Retrieval has a relevance floor.** Only chunks with cosine similarity ≥ `SCORE_THRESHOLD` (default `0.25`, `src/rag.py`) are used. Below that, the pipeline says it doesn't know and **does not call the LLM**.

## Run it
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # add GEMINI_API_KEY (https://aistudio.google.com/apikey)
python data/sample/generate_sample_data.py   # optional demo files
uvicorn app:app --reload        # http://127.0.0.1:8000
```
API docs: `/docs`. Endpoints: `POST /api/upload`, `GET /api/documents`, `DELETE /api/documents/{name}`, `POST /api/chat`, `GET /api/health`.

## Project layout
```
app.py                  FastAPI app (API + serves the UI)
static/                 responsive web UI (index.html, style.css, app.js)
src/
  loaders.py            PDF/TXT/CSV → LangChain Documents
  chunking.py           type-aware chunking (token-based prose, atomic CSV rows)
  vectorstore.py        Chroma persistence + relevance-score filtering
  rag.py                the pipeline: ingest() and answer()
  llm.py                the ONLY place that talks to Gemini — swap providers here
data/sample/            bundled demo files (generated by generate_sample_data.py)
eval/                   golden Q&A set + evaluation harness (not part of pytest)
tests/                  offline unit tests (fakes.py mocks the LLM/embeddings)
```

## Tests / eval
```bash
pytest -q                 # offline, no API key needed
python -m eval.run_eval   # live, needs GEMINI_API_KEY
```
